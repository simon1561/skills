# 数据格式

文件名都是库里笔记的文件名（`index.tsv` 第三列），例如 `2026-10-08 德合大道无为——2026年中期致合伙人信.md`。

## 摘要（`weekly_digest.py add`）

```json
{
  "<笔记文件名>": {
    "gist": "一两句：作者的主要结论。",
    "points": ["要点一，含关键数字", "要点二", "要点三"],
    "quotes": ["一句逐字出自原文的话"],
    "kind": "访谈 | 评论 | 分析 | 纪要 | 其他",
    "source": "原始发布 | 完整译文 | 节选整理 | 二手评论",
    "substance": "信息含量和局限，一句话。",
    "category": "AI 与科技 | 公司与行业 | 投资 | 思维与决策 | 其他"
  }
}
```

已有摘要的条目只给要改的字段即可，例如 `{"<文件名>": {"source": "节选整理"}}`。

## 分档（`weekly_digest.py plan`）

```json
{
  "overview": ["本周推荐逻辑，第一段", "第二段"],
  "question": "本周最拿不准的取舍，问成具体的二选一？",
  "topics": [
    {"name": "拼多多与 Temu", "files": ["<文件名>", "..."], "note": "这组怎么读。"}
  ],
  "outside": ["<邻近探索的文件名>"],
  "ratings": {
    "<文件名>": {
      "level": "精读 | 浏览 | 可跳过",
      "reason": "解决什么问题＋独有信息＋为何值得这个时间。",
      "action": "精读两段：……；其余浏览。",
      "focus": [{"from": "段落开头十几个字", "to": "最后一段开头十几个字", "why": "这段的标签"}],
      "version": "主版本 | 有补充 | 无新增 | 有纠错",
      "flags": ["创始人自述数据，未经核实"]
    }
  }
}
```

- 每篇都必须有 `ratings`；`action`、`focus`、`version`、`flags` 按需要给。
- `focus` 从含 `from` 的段落标到其后第一个含 `to` 的段落（含两端），比对时忽略空白；标题也算段落。起止句要选在全文里不易重复的句子。
- 邻近探索的文章也要有 `ratings`（通常是浏览），它在书里单独成一部分。
