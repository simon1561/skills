# 报告写作规范

## 一、职责与优先级

本 Skill 只负责三件事：

1. 结构清晰，格式规范；
2. 章节安排和全文框架合理；
3. 使用严肃、平视、克制的报告文风。

内容由用户要求和当前调研任务决定。可以根据任务新建文档，也可以补充新信息、更正旧内容、调整结论或重组全文。本 Skill 不判断模型可以研究什么、补充什么，也不提供具体分析方法。

优先级如下：

1. 用户明确要求的任务、结构、篇幅和交付形式；
2. 当前调研形成的事实、判断、计算、边界和不确定性；
3. 结构清晰、低阅读成本和平视表达；
4. 本 Skill 的默认格式。

文风和格式规则不得成为删除、弱化或扭曲重要内容的理由。纯粹修改表达时保持原意；任务包含新建、补充或更正时，根据当前调研结果正常处理，不受既有文档内容限制。发现内容可能有误时，按当前任务核实，或明确标出矛盾与不确定性；不用文字润色掩盖矛盾。

用户明确要求的经营建议、强结论、修订记录、证据冲突和既有模板都属于交付内容，不能以“平视”“克制”或默认格式为由弱化。默认呈现当前有效状态；用户要求保留变化过程或可复核底稿时，按要求保留相关旧值、变更原因、来源和方法。

## 二、全文框架

### 2.1 先确定报告要回答的问题

写作前先识别报告目的、主要读者和需要回答的核心问题，再确定章节。不要按资料取得顺序、调研过程或模型思考顺序堆放内容。

每个主要章节应当回答一个相对独立的问题。相邻章节之间应有清楚的并列、递进、因果或总分关系；如果关系说不清，检查章节是否需要合并、拆分或调整顺序。

已有框架合理时沿用；用户要求重构或现有框架明显增加理解成本时再调整。不要为了显示完整而机械套用固定模板。

### 2.2 使用最小充分结构

结构刚好承载内容即可：

- 一段能说明的内容，不拆成多个小节；
- 一个章节连续处理多个独立问题时，增加必要的下级标题；
- 同一层级、同一组内容只选最适合的一种主结构信号，避免标题、编号、项目符号和加粗标签重复表达层次；
- 表格已经清楚呈现的字段，不在表后逐项复述；
- 简短任务不扩展成完整报告，长篇报告也不把复杂逻辑压成少数大段；
- 章节体量相差明显时，检查是否存在过度拆分、内容错位或尚未分层。

“最小充分”指删除冗余，不是追求最短。删除一个结构单元后，如果会损失独立问题、计算可复核性、关键边界、行动条件或图表含义，该单元就不是冗余。

长篇正式报告可根据需要设置摘要、目录、正文、结论、口径说明、来源和附录；研究备忘录通常只保留结论、分析和来源等必要部分。用户提供结构或模板时，以用户要求为准。

用户或既有模板明确指定的 frontmatter、标题语言、章节顺序、表图编号、图注位置和视觉标签优先于默认格式。没有获得重构授权时，不为追求统一而改动稳定的模板结构和外部引用锚点。

### 2.3 摘要、正文和结论各司其职

- 摘要直接给出全文最重要的答案、主要依据和关键边界，不预告“后文将讨论什么”；
- 正文展开证据、解释、比较和限制条件；
- 结论重组全文认识，回答研究问题及其适用范围，不逐段复述正文。

摘要和结论可以出现同一核心认识，但粒度和作用应当不同。相邻位置不要重复同一句判断。

## 三、章节与段落

### 3.1 章节内部组织

复杂章节优先采用“判断—依据—解释—边界”的顺序，让读者先知道本节回答了什么，再理解证据和限制。简单事实不必套用四步结构。

章节开头可以先给方向性结论，后文再展开数据；章节结尾只有在需要收束多段分析或承接下一章时才设置小结。

标题使用准确的名词短语或克制的结论句，不使用悬念、设问、情绪化判断和认知反转。标题编号服从全文既有格式。

### 3.2 段落和句子

一个段落承担一个主要任务。多组数字、两个以上插入说明或多层逻辑关系挤在一句时，拆句、分段或改用表格。

- 结论及其关键边界放在同一句或相邻句；
- 括号只放简短定义、口径和数字，不承载完整论证；
- 多对象比较减少连续使用“其”“前者”“后者”，必要时重复名称；
- 承转句只说明相邻内容的关系，不评价哪一层“更深”或“更值得关注”；
- 长短句交替，避免连续使用结构相同的句子。

### 3.3 并列、比较和表格

- 简短并列用项目符号，需要顺序或逐项展开时用编号；
- 多对象重复比较相同字段时，优先使用表格；即使只有两个对象，只要表格能明显降低比较成本，也可以使用；
- 同类对象尽量使用相同维度和顺序，缺失项按证据边界标明“当前材料未提供”“公司未披露”“未公开”或“不适用”；
- 口径不同的指标应在表头、正文或注释中明确，不用版式制造可比性；
- 表后只保留需要跨行、跨列或结合口径才能得到的认识，不复述单个单元格。

## 四、文风：严肃、平视、直接

### 4.1 与读者平视

以用户指定的读者为准；未指定时，假定读者具备基本领域背景，并对理解结论不可缺少的术语和口径作简短说明。平视不等于省略必要解释。直接陈述判断及其依据、口径和边界，不安排读者应当怎样理解或决策。

减少以下表达：

- “先看……再看……”“必须理解”“需要牢记”“只有理解……才能……”；
- “如果只看……就会误判”“很多人忽视”“常被低估”；
- “真正”“本质”“深层”“这才是分野”等抬高作者位置的词；
- “答案是……”“这揭示了……”等演讲式揭晓；
- “一句话概括”“顺带说”“潜台词是”等口语旁白。

材料缺失时，按实际证据边界写“现有材料未提供租金条款”或“公司未披露租金条款”，不写“需要注意的是，本文未能取得租金条款”。不要把“当前材料没有”升级成“公开信息不存在”。

面向任务指定对象的经营建议、决策建议和行动要求是报告内容，不属于对普通读者说教。保留建议的动作、对象、依据和适用条件，不要为了显得平视而改成“可适当关注”等空泛表达。

### 4.2 不依靠认知反转推进

“不是 A，而是 B”“看似 A，实际上 B”等结构并非禁用，但不应成为全文主要的推进方式。先判断它是否承担必要的定义、排除、纠错或对比：

- 只是制造揭晓感时，改为直接陈述事实及其关系；
- 承担必要逻辑时，保留这层关系，换成更平实的表达或直接保留；
- 不要为了避开某个句式而删除否定、转折或比较的一端。

例如：

- “两家公司看似利润率接近，实际口径不同”可写为“两家公司披露的利润率接近，但统计口径不同”；
- “该指标是门店 EBITDA，不是公司净利润；两者不能直接比较”包含必要的口径排除，可以保留；
- “真正决定结果的是资本投入”可直接写为“结果取决于资本投入”，避免借“真正”制造揭晓感。

### 4.3 只呈现当前有效的研究状态

正式报告不记录与结果无关的写作过程和版本来回，例如“最初认为”“上一版写成”“经过反复讨论后”。直接呈现当前有效的事实、分析和结论。

影响读者判断结果可靠性的研究方法、计算口径、调整方式和假设必须保留。“采用统一口径重新计算”“资产年龄假设为 7—8 年”属于方法和边界，不是应当删除的过程旁白。

用户明确要求修订记录、前后差异或研究底稿时，相关过程本身就是交付内容，应当保留并与正式结论分区呈现。

### 4.4 判断强度准确

措辞应与当前证据和分析结论的强度一致：

| 内容状态 | 常用表达 |
|---|---|
| 直接事实或定义 | 为、包括、达到 |
| 多项证据方向一致 | 显示、表明、支持 |
| 样本现象但不能证明因果 | 呈现、与……一致、在现有样本中 |
| 样本有限或存在其他解释 | 可能、尚不能排除、无法单独归因 |
| 口径不可比或数据缺失 | 无法确定、不能直接比较、不能据此排序 |
| 情景测算 | 在该假设下、结果取决于、若……则…… |

不要为了显得有力而绝对化，也不要为了显得谨慎而把已经成立的判断写得含糊。

证据支持强结论时，保留“决定”“不能”“仅由”等必要强度，并用适用范围和前提控制边界；不要机械添加“可能”“一定程度上”等词稀释答案。

## 五、数据、证据与更新一致性

本节只规范已有材料和当前任务所需内容的呈现，不规定研究方法，也不要求为了形式齐全新增计算、分类或证据说明。

- 区分披露事实、自行计算、估算、推断、情景假设和公司或第三方观点；
- 保留重要算式、分母定义、假设和适用范围；
- 实际值、假设值和推断值分别标明，情景数字不写成已实现结果；
- 同类指标统一展示单位和精度，不用多余小数制造精确感，也不因统一展示改变原始值、有效位或结论边界；
- 口径不同则明确说明，不把不同口径的数字直接排序；
- 关键来源靠近相应事实或表图，长篇报告可在附录集中列出完整来源。

图表应把材料和交付场景能够支持的标题、期间、单位、指标口径、实际值或预测值、样本范围和来源呈现清楚；缺失信息标明边界，不补造。不适用的项目不必机械补齐。预测值、区间和缺失值应有清楚的视觉或文字标识，不用版式制造不存在的可比性。

向既有文档补充或更正内容后，检查摘要、正文、表格、图片、结论、来源和交叉引用是否一致。不要让已经失效的新旧数字、口径或判断同时留在最终文档中。

## 六、格式规范

### 6.1 标题、表图和加粗

- 标题层级连续，同级标题采用一致的语法结构；
- 新建报告的表图编号连续，每张有标题，正文有对应引用；既有模板或局部更新默认保留原编号、引用锚点和外部链接，只有在用户要求或整体重排时才重新编号；
- 金额、比例和数量混合的表格，把单位放入对应列名，不用一个笼统单位覆盖整张表；
- 普通正文的加粗只用于少量关键判断或描述性标签，不整段加粗；
- 同一自然段只设置少量视觉锚点，不连续堆放加粗句。

CommonMark 中，加粗内容以中文标点结尾且闭合标记后紧跟正文，可能导致 `**` 泄漏：

- 错误：`**结论如此。**接下来……`
- 正确：`**结论如此**。接下来……`

### 6.2 文字和单位

- 中文正文使用全角逗号、分号、冒号和句号；千分位、英文、代码与结构化数据中的半角符号除外；
- 默认使用公制；换算自英制资料时说明必要的换算口径；
- 英文只保留通用缩写和专有名词，专有名词首次出现可用“中文（英文）”；
- 不使用读者需要解码的内部代号；用户或来源中的正式标签、对象编码和定位符可以保留，并在读者需要时简短解释；
- 写入 Obsidian 的正文默认不加 YAML frontmatter，用户或既有模板要求时除外。

### 6.3 空行与段落分隔

写入 Obsidian 的文档，正文段落之间不留空行，直接换行；下面列出的受保护结构前后仍需留空行。Obsidian 默认关闭「严格换行」，单个换行就会另起一行，段落间再留空行会让正文显得松散。

空行只保留在这些位置，它们决定解析结果，删掉会改变文档结构：

- 标题之前，用于分隔章节；
- 水平分隔线（`---`、`***`、`___`）前后。紧跟在正文下面的 `---` 是 setext 二级标题的下划线，会把上一段变成标题；
- 表格、列表、引用块、callout、代码块（含缩进代码）、LaTeX 块、HTML 块、脚注定义和链接定义的前后。

标题正下方不留空行，下一行是另一个标题时同样不留。交付到 GitHub、代码仓库等按标准 Markdown 解析的场合，仍按标准在段落之间留空行。

判定逻辑在 `scripts/blank_lines.py`，`scripts/tidy_blank_lines.py` 按同一逻辑清理：默认只打印 diff，确认后加 `--apply` 写入。不要另写清理脚本，判定分散会产生分歧。

`scripts/check.py` 只检查 Markdown 文本。DOCX、PDF、飞书文档、HTML 等其他介质采用本 Skill 的结构和文风原则，并按各自格式检查，不机械套用 Markdown 标记规则。

## 七、交付前检查

运行 `scripts/deliver.py <文件路径> --target obsidian|markdown`。目标为 `obsidian` 时，它先预览空行清理的 diff，确认无误后加 `--apply` 写入，再做完整格式检查；目标为 `markdown` 时不做清理，直接检查。退出码：0 表示自动检查通过、仍需人工复核，2 表示有待处理项，1 表示用法错误。

只做检查不清理时，运行 `scripts/check.py <文件路径> [--target obsidian|markdown]`。`--target` 决定空行一项如何判定：`obsidian` 时可删空行计入格式问题，`markdown` 时段落间空行应当保留、该提示不适用，不传则只作提示、不影响是否通过。

读完整输出，不要只看结论行。空行、编号、层次、文风等提示都排在结论行之前，过滤输出会把它们一并丢掉。脚本不能判断一句话是否承担必要逻辑，也不能替代全文阅读。

### 框架与结构

- 全文是否回答了报告的核心问题；
- 各章节职责是否清楚，顺序和相互关系是否合理；
- 摘要、正文和结论是否各司其职；
- 是否存在过度分层、大段堆积、章节失衡或重复论证。

### 文风与表达

- 是否直接陈述，没有指导读者、预设误判或抬高作者；
- 是否依靠反转、揭晓、金句和比喻推进论述；
- 删除修辞后，原有事实、否定、转折和逻辑关系是否仍然完整；
- 判断强度是否准确，关键边界是否靠近结论；
- 是否把写作过程与必要的研究方法区分开。

### 格式与一致性

- 标题层级、表图编号、引用、单位、标点和加粗是否正确；
- 比较维度、表头、来源和口径说明是否容易定位；
- 新增或更正内容后，全文是否仍然一致；
- 是否为了版式整齐、篇幅压缩或文风克制而损失重要内容。
