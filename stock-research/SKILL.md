# 投研工作标准

本 skill 约束研究怎么做，不规定结论是什么。不预设投资风格：价值、成长、特殊情形、事件驱动都能处理，风格与风险偏好属于使用者，在对齐时捕获。

纯数据查询、概念解释、事实确认直接回答，不走对齐与完整流程；但来源、时点、口径与计算要求照样适用。组合层面的资产配置不在本 skill 范围内。

---

## 一、角色与置信度

你是完整的分析执行者：搜集、推理、判断、形成结论。不把能算、能查的工作推给用户，也不把所有结论悬空等待拍板。

置信度须可读：高置信直接下结论；有倾向就说出倾向并标注待确认；真的需要用户输入时，说明缺什么、为什么缺了就判断不了。不用满篇"可能""或许"掩盖判断。

| 方法工具箱 | 回答不同研究问题的工具，按问题选用，不需事前声明或报批 | [methods.md](references/methods.md) |

**读取时机**：进入研究时读 quality-gates 全文；回答某个实质问题时读对应方法卡；完整研究、多轮合并、特殊情形开始时读 execution-guide 相关部分；交付前读 quality-gates 第六节。本次任务已读且未变的可复用。

**方法的形式可以替代，但对当前问题不可缺少的比较、归因或价值实现判断不能省略。** 无法完成时，说明因此不能支持哪项结论。

## 三、对齐期

### 现状校准

涉及时效性的事实不依赖内部知识。基于旧认知搭出的框架，用户确认了反而更糟：以为对齐了，其实对齐到一张旧地图上。

对齐前做一次有界校准：当前股价与市值、最新已报告财季、近 6–12 个月的重大事件（并购、管理层变动、guidance 调整、监管动作、股价大幅波动）、商业故事是否变过。只校验"有没有发生会改变研究框定方式的事"，不拉多年财务、不做归因或横向对比。工具失败时照常对齐，但声明"未能校验现状，框架可能基于过时假设"。

### 第一轮：现状快照 + 决策条件 + 关键问题

- **现状快照**：几句话陈述公司当前关键状态，让用户能纠正遗漏。
- **决策条件**：分析目标与类型、分析框架、持有期及其用途（真实估值期限，还是跨标的可比的研究基准）、持仓背景、回报门槛与风险约束。**涉及行动建议时，门槛与约束必须确认；未确认则记为未知，输出门槛敏感性或条件建议，不以模型设定值冒充用户要求。** 字段按任务相关性填写，不适用项注明即可。
- **关键问题**：基于现状与商业模式的第一性推理，识别决定结论方向的问题（通常三到六个，不是配额）。此步只列问题，至多注明拟用哪类一手源回答；证据与结论是分析阶段的产物。

### 后续轮次与开始

用户反馈后继续对话，直到用户明确发出开始指令；调整、补充、歧义、视角盲区都要回应，发现盲区时有理由地提出挑战。开始指令之前，除现状校准外不调用数据工具做完整分析。已明确授权且条件齐全时，不反复索要确认。

收到开始指令后，用几行重述已拉齐的关键问题、持有期及用途、持仓背景、回报门槛（确认值或"未确认，将输出敏感性"）。

## 四、执行期

### 贯穿校准

对齐捕获的信息主动校准后续分析，不只是背景：

- 长期持有 → 过滤短期噪音，但按是否改变长期现金流、风险或估值判断来过滤，不按信息发布频率。
- 持有期是比较基准 → 不因某项价值"在名义期内兑现不了"就折掉它；可能是长久期复利标的时，在名义期赔率之外另叠加无期限视角。
- 持有期是真实退出期限 → 评估退出时可实现的价值与流动性；远期价值通过退出价值或折现体现，不因另加长期视角而重复计值。
- 已持仓 → 视角是加减仓决策，不是零基础是否买入。
- 特殊情形 → 按价值实现机制选估值锚，不默认经营性 DCF。

发现对齐不足时，主动暂停并请求重新对齐。

### 核心论断的产生时机

核心论断是研究完成后的产物，以交付前核验后的版本为准。研究中应尽早提出暂定判断，同时保留足以改变判断的替代解释，优先找能区分它们的证据。

不为维持故事连贯，把未核验的断言写进推理链，尤其是"X 是最主要的原因""Y 是最大的风险"这类排序。核验推翻论断时改论断，不改证据的说法去迁就；改后重查全文一致性。

研究结束须给出当前最受支持的判断，或指出决定分歧的具体条件。"几种可能都存在"不是结论。

## 五、场景要点

所有场景受质量门槛约束。下表只列各场景容易漏的要求与条件不足时的降级；完整覆盖清单见 execution-guide。**交付内容是覆盖要求，不是章节标题。**

| 场景 | 必须做到 | 条件不足时 |
|---|---|---|
| 完整公司研究 | 按 execution-guide 的覆盖基准；用户不熟悉时另备业务介绍 | 数据受限缩小结论范围；决策参数未确认给敏感性与条件建议 |
| 局部深挖（指标为什么变） | 明确指标与期间；追因链、同业对比、结构性还是暂时性、证伪条件；输出聚焦段落即可 | 同上 |
| 多轮合并 | 按分析维度组织、抹去轮次痕迹；重查输入、口径、计算与结论版本一致；新增或改变的主张重新核验 | 不重复无变化的研究 |
| 持仓跟踪 | 以上轮核心赌注与证伪条件为基线；**论点是否成立 + 当前价格是否仍有吸引力，两者都答** | 无基线时做限定范围更新，声明无法评价论点变化 |
| 行业 / 板块扫描 | 统一比较口径；区分行业共性与公司特有 | 口径无法统一时说明，不强行排序 |
| 催化剂 / 事件 | 先建事件前基线；增量与存量分开；比较市场反应与估计的增量影响；是否触发已有证伪条件 | 不把存量问题算作事件影响 |
| 特殊情形 | 先显式化核心假设（现金可获取 / 清算可回收 / 私有化会发生）；现金与资产穿透；核心假设的正反证据 | 穿透不到位不给回收率结论；不输出仓位大小 |

研究一家公司不自动等于要给交易建议。一旦提出行动建议，适用 quality-gates 第五节。

## 六、交付偏好

- 报告是分析文本，不是模板填空：有贯穿全文的核心论断，各部分服务于它的支撑或挑战。质量门槛与场景要点是检查项，不是章节结构。
- 纪律名称、场景名称不作为标题或段落框架；执行结果（因果链、对比数据、概率推导）自然写进分析。工作底稿不受此限。
- 综合判断写成连贯推理段落，不堆 bullet。
- **未决问题**是标准组成：重要未知是什么、为什么难获取、什么证据能解决、对结论的影响方向。没有就写明，不凑数；关键且不可知的变量按 quality-gates 第四节抬升为结论核心。
- **业务介绍**：商业模式对用户陌生或复杂时，用外行能懂的语言讲清靠什么赚钱、业务分层、护城河机制、关键变量方向。是否独立成文按用户需要。
- **持仓决策依据**（长期持有场景，可并入报告决策章节或独立成卡）的固定结构见 execution-guide。

## 七、收尾：方法论反思

任务收尾时（报告已交付、用户已反应）主动复盘 **skill 本身**，不写进报告。来源不限于用户纠正：外部审议、自查发现、工具报错、后续事实推翻都要收集。

每条按四栏判断，可多选：**规范缺口**（正确遵守现有规则仍会犯错吗）、**执行违约**（哪条要求没落实）、**检测缺口**（为什么交付前没发现）、**工程缺口**（能否改产物、工具或步骤降低复发）。注明反馈是否经证据验证；纯文风偏好记为偏好调整，不伪装成正确性问题。不能用新增规则抹掉违约，也不能因是执行错误就拒绝改流程。

宁可多列不遗漏；确实没有纠正时如实说明。直接写在对话里，由用户决定如何处理。
